    t1 --> sse -->|"push: token-by-token as the LLM generates"| widget
    t2 --> rest -->|"pull: poll every 60 s"| bell
    t3 --> rest -->|"pull: refetch after each mutation<br/>and on route change"| pages
    rest -->|"refresh before the 1 h JWT expires"| auth

    classDef push fill:#1f7a4d,stroke:#0d3d26,color:#fff
    classDef poll fill:#8a5a00,stroke:#4d3200,color:#fff
    class sse,widget push
    class bell,pages,auth poll

    note["Three mechanisms, deliberately chosen:<br/>1. SERVER-SENT EVENTS for AI answers — the only place where sub-second,<br/>&nbsp;&nbsp;&nbsp;token-level latency matters. One-directional, so SSE beats a WebSocket:<br/>&nbsp;&nbsp;&nbsp;plain HTTP, survives the nginx proxy, auto-reconnects.<br/>2. SHORT POLLING (60 s) for the notification bell — holds, review decisions,<br/>&nbsp;&nbsp;&nbsp;overdue alerts. Cheap, stateless, no extra infrastructure.<br/>3. REFETCH-ON-MUTATION for everything transactional (loans, fines, uploads):<br/>&nbsp;&nbsp;&nbsp;the mutation response is the new state, so the UI updates in the same round trip.<br/><br/>NOT implemented: WebSockets and Postgres LISTEN/NOTIFY. Listed under Future Work —<br/>they would replace mechanism 2 with true push for multi-user circulation desks."]

Figure 5 — Flow 1: Upload → RAG Ingestion

SDD Flow 1. Asynchronous worker pipeline: extract, chunk, embed, index. docs/diagrams/flow-upload-ingestion.mmd

%% SDD Flow 1 — Document upload -> RAG ingestion pipeline (async)
sequenceDiagram
    autonumber
    actor U as Researcher / Student
    participant FE as Next.js upload form
    participant API as Go API (/api/v1/media/upload)
    participant S3 as MinIO
    participant DB as PostgreSQL
    participant Q as Redis queue
    participant W as Ingestion worker
    participant EMB as MiniLM embedder

    U->>FE: selects file + fills title, abstract, keywords, access tier
    FE->>API: POST multipart/form-data (Bearer JWT)
    API->>API: validate size, extension against chk_media_format, role
    API->>S3: stream binary -> object key
    S3-->>API: object key
    API->>DB: BEGIN
    API->>DB: INSERT media_items (item_type, format, status, access_tier, file_path)
    API->>DB: INSERT media_metadata (abstract, keywords, tags, language) — 1:1, FTS trigger fires
    opt research or project upload
        API->>DB: INSERT research_papers / student_projects (1:1 specialisation)
    end
    API->>DB: COMMIT
    API->>Q: LPUSH ingestion job {item_id, object_key}
    API-->>FE: 201 Created (ingestion_status = NULL, "processing")
    FE-->>U: item appears immediately — badge shows "indexing"

    Note over W,EMB: Asynchronous — the user never waits for embedding.
    W->>Q: BRPOP job
    W->>S3: download object
    W->>W: extract text (PyMuPDF / docx), detect language
    W->>DB: SELECT rag_index_state.content_hash
    alt content hash unchanged
        W-->>DB: skip — already indexed
    else new or modified content
        W->>W: chunk at 512 tokens with 50-token overlap
        W->>EMB: embed each chunk (local, no API cost)
        EMB-->>W: 768-dim vectors
        W->>DB: UPSERT vector_embeddings (item_id, chunk_index) — UNIQUE guards crash-retry duplicates
        W->>DB: UPSERT rag_index_state (content_hash, chunk_count, indexed_at)
        W->>DB: UPDATE media_items SET ingestion_status = 'indexed'
    end
    alt extraction or embedding fails
        W->>DB: UPDATE media_items SET ingestion_status='failed', ingestion_error=<reason>
    end

Figure 6 — Flow 2: RAG Query with Access Control

SDD Flow 2. Hybrid retrieval, tier filtering before prompt assembly, Groq with Gemini fallback, SSE streaming. docs/diagrams/flow-rag-query.mmd

%% SDD Flow 2 — RAG AI query with access control (streamed over SSE)
sequenceDiagram
    autonumber
    actor U as User (browser)
    participant FE as Next.js frontend
    participant NG as nginx
    participant API as Go API (/api/v1/ai/chat/stream)
    participant R as Redis cache
    participant RAG as Python RAG service
    participant DB as PostgreSQL + pgvector
    participant LLM as Groq (primary)
    participant GM as Gemini (fallback)

    U->>FE: types a question in the AI widget
    FE->>NG: POST /api/v1/ai/chat/stream (Bearer JWT, Accept: text/event-stream)
    NG->>API: proxy (30s timeout for /ai/)
    API->>API: middleware.Authenticate -> user_id + role_tier from signed JWT
    API->>R: GET cache[hash(query, role, lang)]
    alt cache hit (< 5 min old)
        R-->>API: cached grounded answer
        API-->>FE: SSE stream of cached answer (no Groq call, quota preserved)
    else cache miss
        API->>RAG: POST /query {query, user_role, language, history}
        opt rewrite_query = true
            RAG->>GM: rewrite the query for retrieval
            GM-->>RAG: normalised query
        end
        RAG->>RAG: embed query with paraphrase-multilingual-MiniLM-L12-v2 (768-dim, local)
        par hybrid retrieval
            RAG->>DB: vector search — cosine ANN over HNSW index
        and
            RAG->>DB: keyword search — PostgreSQL FTS (English + Bangla configs)
        end
        DB-->>RAG: candidate chunks + owning media_items
        RAG->>RAG: reciprocal rank fusion, then drop every chunk whose<br/>media_items.access_tier outranks the caller's role_tier
        Note over RAG,DB: Access control happens BEFORE the prompt is built,<br/>so restricted documents can never leak through the model.
        RAG->>LLM: grounded prompt (context + citations), model tier chosen by query size
        alt Groq responds
            LLM-->>RAG: streamed tokens
        else Groq unavailable / rate-limited
            RAG->>GM: same prompt
            GM-->>RAG: streamed tokens
        end
        RAG-->>API: SSE token stream + source_doc_ids
        API->>DB: INSERT ai_chat_messages (query, response, source_doc_ids, model_used)
        API->>R: SETEX cache 300s
        API-->>FE: SSE token stream
    end
    FE-->>U: answer renders progressively, with clickable citations

Figure 7 — Flow 3: Barcode Borrow and the Fine Cycle

SDD Flow 3. Circulation desk transaction plus the nightly idempotent fine worker. docs/diagrams/flow-borrow-fine.mmd

%% SDD Flow 3 — Barcode borrow at the circulation desk, plus the nightly fine cycle
sequenceDiagram
    autonumber
    actor L as Librarian
    participant SC as HID barcode scanner
    participant FE as Circulation desk UI
    participant API as Go API (/api/v1/library/circulation)
    participant DB as PostgreSQL
    participant FW as Fine worker (cron)
    participant MAIL as Brevo SMTP
    actor M as Member

    L->>SC: scans member card, then book label
    SC->>FE: keystrokes "M-A0000000\n" and "B-1F2E3D4C\n"
    FE->>FE: strip trailing \r\n appended by the scanner
    FE->>API: POST /circulation/checkout {member_barcode, item_barcode}
    API->>API: RequireRole(librarian, administrator)
    API->>DB: BEGIN
    API->>DB: resolve barcodes -> user_id, catalog_id
    API->>DB: check outstanding fines vs FINE_BLOCK_THRESHOLD_BDT
    alt member blocked by unpaid fines
        DB-->>API: total fines >= threshold
        API-->>FE: 403 "settle outstanding fines first"
    else eligible
        API->>DB: INSERT loans (due_date = now + LOAN_PERIOD_DAYS)
        Note over DB: idx_loans_active_user_item (user_id, catalog_id)<br/>WHERE return_date IS NULL — blocks a duplicate active loan
        API->>DB: UPDATE library_catalog SET available_copies = available_copies - 1
        API->>DB: INSERT audit_log
        API->>DB: COMMIT
        API-->>FE: 201 loan created, due date shown
    end

    Note over FW,DB: Nightly, independent of any user session.
    FW->>DB: SELECT loans WHERE return_date IS NULL AND due_date < now()
    FW->>FW: amount = days_overdue * FINE_RATE_BDT_PER_DAY, capped at MAX_FINE_PER_LOAN_BDT
    FW->>DB: INSERT INTO fines ... ON CONFLICT (loan_id) DO UPDATE
    Note over DB: UNIQUE(loan_id) makes the nightly run idempotent —<br/>no duplicate fine row per overdue loan
    FW->>DB: INSERT notifications
    FW->>MAIL: overdue email
    MAIL-->>M: "Your book is overdue — fine now BDT X"

    M->>FE: pays via bKash/Nagad OTP or requests in-person cash
    FE->>API: POST /fines/{id}/pay/initiate -> /confirm (or /pay/cash)
    API->>DB: payment_sessions -> payments -> fines.status = 'paid'
    API->>DB: return book -> restore available_copies, fulfil the oldest active hold
